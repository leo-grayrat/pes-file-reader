# 事件表打包值解码报告（bit-field 分析）

- 数据：297 行（ML0/ML1/ML13 各 99）

- 对照 ID 集：EDIT 球员 23086 个（72..146167）、ML 注册键 18390 个（1..399041）

## 1. v2_raw 就是 f2（字段冗余，非独立字段）

- `v2_raw >> 16 == f2_hi`：**297 / 297**
- `v2_raw & 0xFFFF == 0xFFFF`（哨兵）：**294 / 297**
- → **v2_raw 是 f2 的原始 32 位表示**（高16位=球员引用，低16位=0xFFFF 哨兵）。
  此前把 v2_raw 当独立数值字段做相关性，得出「与所有字段无关」是**解析层面的误判**：它本就是 f2，而 f2 是实体引用，自然与财务字段无关。

## 2. 空值哨兵约定（重要，防误判）

| 字段 | 空值形态 | 命中行数 |
|---|---|---|
| v6 (u32) | `0xFFFFFFFF` | 39 / 297 |
| v2_raw/f2 低16位 | `0x0000FFFF` | 294 / 297 |
| f2_hi | `0x0000FFFF` | 32 / 297 |
- **教训**：u32 的「空」是 `0xFFFFFFFF`，16位分量的「空」是 `0xFFFF`；判断为空不可默认 `==0`（probe48 曾因此误判 v7→v6 结论）。

## 4. v4 / v8 高16位 = 分类枚举（非随机量）

### v4_hi 取值分布
  - `0` (0x0000)：132 行
  - `1` (0x0001)：126 行
  - `2` (0x0002)：24 行
  - `4` (0x0004)：6 行
  - `16384` (0x4000)：6 行
  - `5` (0x0005)：3 行

### v8_hi 取值分布
  - `0`：243 行
  - `1`：18 行
  - `2`：15 行
  - `4`：6 行
  - `8`：6 行
  - `3`：3 行
  - `6`：3 行
  - `9`：3 行

→ v4_hi 仅 **6** 个取值、v8_hi 仅 **8** 个取值，明显是**枚举/标志位**而非连续量；低16位才是每行不同的实体 ID。

## 5. v5_hi / v6_hi：注册索引假说的验证

- **排除「球队 ID」**：EDIT 头部 team count = **694**，而 v5_hi 值域 25..16422、v6_hi 值域 25..65535 —— 均**远超**球队总数，故不是球队编号。
- **支持「注册索引」**：注册键在 ≤20000 区间有 **13980** 个（密集区），v5_hi/v6_hi 值域正好落在该密集区内。
- v5_hi 落在注册键：**291/297**（98%，同值域随机基线 80% → **超基线 18%**，确证为注册索引）
- v5_hi → reg → db_id → EDIT 取到名字：**99/297**（33%，与 option file 覆盖 41% 量级吻合）
- 解析样例（真实球员名，证明链路可用）：['贝尔蒂尼', '姆巴耶·迪亚涅', '韦斯·摩根', '雷莫·弗罗伊勒', '华莱士', '里卡多·萨波纳拉', '格雷罗', '里卡多·罗德里格斯', '卡米尔·格罗西茨基', '莫雷蒂', '罗伯特·斯诺德格拉斯', '达内尔·福隆']
- **语义推论**：v5/v6 的高16位是**模板固定的注册索引**——模板存索引、各档用各自注册表解析到不同球员，这正好解释「财务列三档完全相同、而球员不同」。

## 6. v3 大值 = (56357 << 16) | x 打包

- 大值行 18 条，高16位分布：**[(56357, 18)]**
  - 高16位 `56357`（0xDC25）共 18 条；低16位 0x4AC6..0x5065
- 检验 56357 身份：在 EDIT id 集？**False**；是注册键？**False**；是注册值(db_id)？**False**
- → 56357 不属于任何已知 ID 集，且低16位在 0x4AC6..0x5065（19142..20581）变动
  → **判定为打包值/特殊类别标记，绝不是金额**。此前「全场 Σ=6.6 万亿欧」是被它带偏的产物。
