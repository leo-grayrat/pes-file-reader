# REPLAY 事件区槽 blob 探查报告

- 样本：`decoded/rep_REPLAY00000000.data`（660 帧 × 8112B 事件流）
- 目的：验证 HANDOFF 主线假说「248B blob 剥头后同槽跨帧差分/异或，找 float32 坐标」
- 日期：2026-08-30
- 脚本：`replay_blob_probe.py`、`replay_coord_probe.py`

## 结构背景（replay_analyze.py 已证）

```
事件流 = 660 帧 × 8112B（帧大小/帧数由头部 +0x58/+0x60 闭合，50/50 样本）
帧     = 16B 帧头（含 u16 时钟，步长 5/10）
        + 256×16B 状态表（静态初始化，见下）
        + 4000B 事件区（含 ~10 个球员槽包）
槽     = 12B 头（含槽号 12~21）+ 20×i16 姿态码 + 约 248B blob
```

## 主要发现

### 1. 槽12 blob 的 float32 视角是**假象**（被 NaN 过滤误导）

- 初版分析：92.7% 的 4B 位置跨帧差 |d|<50、43/46 值落在 ±60 → 一度像坐标。
- **真相**：float 解释下大部分值溢出为 NaN/Inf（指数全 1），被 `|x|<1e4` 过滤后只剩"看似合理的稀疏值"。
- 改按 **u32 解释**：blob 首 4 个 u32 是 2.6e9~4.2e9 的**大整数**，**每帧全量刷新**（相邻帧 659/659 不同，约 70% 字节变化），值域稳定无尖峰 → 不是稀疏事件，是**打包状态**。

### 2. 位域分解：无干净坐标模式

- `+0x00`：lo16 相对平稳（57159..60548，±2000）但**量级 ~59000 不符坐标**；hi16 大波动（41000..59000）。
- `+0x0C`：hi16 相对平稳（6500..15000）但同样不符坐标量级。
- 相邻帧 u32 差值：中位 1638 万、P90 5374 万 → 无"小增量连续轨迹"特征。

### 3. 10 个槽全部同构

- 帧0 槽数 10（槽号 12~21），各槽 blob 首 4 个 u32 全部为 2.6e9~4.2e9 大整数。
- 槽13 跨帧同槽12 模式（hi16 波动、lo16 58k~62k 平稳）。

### 4. 状态表是静态初始化

- 帧内 256×16B 状态表，前 8 行为 `[0,0,0,1.0]`（rec0 全 0），**跨帧完全不变** → 非实时位置表。

## 结论

**「回放槽 blob 含 float32 坐标」假说被否定**：

- 回放编码是**动作/状态流**（每帧全量刷新的打包 u32 状态），不是**位置流**（无直接可读的 float32 坐标）。
- 20×i16 姿态码 + 打包状态 blob 的组合说明：位置由动作/动画数据在运行时**重建**，不落盘为坐标。
- 此负结果有保存价值：后续分析**不应**再在该结构内盲找 float32 坐标，应转向「姿态码 i16 序列 vs 帧时钟」或「跨样本同槽差异」等方向（若用户有兴趣）。

## 坑记录

- **float32 盲扫陷阱**：高熵 u32 数据按 float 解释会大量产生 NaN/Inf，若不做 NaN 统计就过滤，会看到"伪稀疏/伪坐标"信号。必须先看 u32 原值分布再决定解释方式。
