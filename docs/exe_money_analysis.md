# ML 资金字段：FL_2023.exe 静态反汇编分析（2026-08-29）

> 本文记录用**社区 Cheat Table 的 AOB 签名**在 exe 中定位资金入口，并反汇编出
> **货币汇率表**的全过程。全部结论来自静态分析（只读 mmap + objdump），
> **不需要运行游戏、不需要玩家提供任何游戏内数值**。

## 一、方法：把社区工具从"结论来源"升级为"代码定位器"

此前（`docs/HANDOFF_v2.md` 教训 5）已提出"社区生态优先"，但执行时只把社区工具
当成**结论来源**（抄偏移、抄单位）。本次改换用法——`resources/CT` 里的
Cheat Table 除偏移外，还含 `aobscanmodule` 签名，而这些签名被作者保证
**在目标 exe 中唯一**，因此可以作为**代码定位器**直接在本机 exe 上定位。

配套脚本：`exe_aob.py`（扫描签名并核对社区实测 RVA）。

## 三、资金入口的指针链

反汇编 `FL_2023.exe+0xEA4C58`（VMA `0x140EA4C58`）：

```asm
140ea42cb:  call 0x1414b6a60            ; 取全局单例
140ea42d3:  mov rdi,[rax+0x48]          ; 预算结构基址 = [[单例] + 0x48]
...
140ea4c53:  call 0x140e63810
140ea4c58:  mov eax,[rdi+0x16ecbf4]     ; ★ 转会预算（CT 表注入点）
140ea4c5e:  mov [rbp-0x3c],eax
140ea4c61:  lea rdx,[rbp-0x3c]
140ea4c65:  lea rcx,[rbp-0x30]
140ea4c69:  call 0x141567c00            ; 金额 → 显示文本
140ea4c81:  call 0x140e64c40            ; 写回 UI
```

CT 表导出的偏移：

| 字段 | 表达式 | 类型 |
|---|---|---|
| 转会预算 | `ptrBudget + 0x16ECBF4` | 4 字节无符号 |
| 薪资预算 | `ptrBudget + 0x16ECC08` | 4 字节无符号（**与前者相距 0x14**） |
| 球员年薪 | `ptrPlayer + 0x15C` | 4 字节有符号 |
| 球员身价 | `ptrPlayer + 0x174` | 4 字节有符号 |

## 四、核心成果：货币汇率表

`0x141567c00` 是薄封装，真正的换算在 `call 0x141565f50`，而后者是混淆跳板
（`jmp 0x144af2120`，落在体积达 398MB 的 `.impdata` 节）。跟随跳板后得到
5 路 switch，由 `[rcx+0x17893f8]`（货币类型）选择：

| case | 指令 | 系数 | 对欧元比值 | 推断货币 |
|---|---|---|---|---|
| 0 | `imul rdx,rdx,0x30d4` | 12500 | 125 | 日元 JPY |
| 1 | `imul rdx,rdx,0x64` | **100** | **1.00** | **欧元 EUR（基准）** |
| 2 | `imul rdx,rdx,0x6e` | 110 | 1.10 | 瑞士法郎 CHF |
| 3 | `imul rdx,rdx,0x5a` | 90 | 0.90 | 英镑 GBP |
| 4 | `imul rdx,rdx,0x1ae` | 430 | 4.30 | 巴西雷亚尔 BRL |

函数内另有多处 `mov eax,[rip+...] ; xor eax,0x1889496c` 形态的常量解密，
属混淆器产物；**但 `imul` 的系数是明文立即数，未被混淆**。

### 结论：金额单位 = 100 欧元（代码级确认）

- 欧元档系数为 **100**，即 **存档金额 × 100 = 欧元显示值**。
- 这把 `HANDOFF_v2.md` 教训 1 的"金额单位 = 100 欧元"从**社区工具运行时实证**
  升级为**游戏代码证明**。
- 佐证：BudgetSetter.lua 的作者特意提示"强烈建议用欧元"，正因其他货币存在
  汇率换算，只有欧元是 1:1 基准。

## 五、存档侧对拍（`bl_ml_probe17.py`）

以"单位 = 100 欧元 + 预算对间距 0x14"为约束，扫描球队记录 +0x560~+0x5B0：

| 偏移 | 跨样本变化 | 万位整数占比 | 判读 |
|---|---|---|---|
| `+0x598` | 203/700 队 | **71.0%** | **强金额特征**，主要候选 |
| `+0x594` | 308/700 队 | 1.0% | 次候选 |
| `+0x59C`/`+0x5A0`/`+0x5A4` | 464~569/700 队 | ~0% | 噪声/指针类，非金额 |

`+0x598` 取值经 ×100 换算后落在 **100 万 ~ 9000 万欧元**，与大师联赛各级别
俱乐部的转会预算吻合：

| 存储值 | 欧元 | 示例队 |
|---|---|---|
| 50000 | 500 万 | 队 33 |
| 300000 | 3000 万 | 队 167 |
| 900000 | 9000 万 | 队 162 |

**据此将 `docs/bl_ml_structure.md` §2.5 的"+0x598 疑预算字段簇"从"疑似"
升档为"转会预算（初始/赛季初分配值）"。**

### 关键观察：ML00000002 是赛季前存档

`+0x598` 在 ML00000002 中**恒为 0**，其余三档有值。这与文档已记载的
"赛季前存档（BL2/BL3）无赛程表"同型，提示 **ML00000002 为赛季前存档**
（赛季未开始，运行时字段尚未初始化）。

**这是对既往差分方式的修正**：`probe14/15/16` 拿 ML00000000 ↔ ML00000013
做差分，二者进度接近故零命中；真正的强对照应是**赛季前 vs 赛季中**。

## 六、全文件对照扫描的发现与假阳性（`bl_ml_probe18.py`）

按"赛季前 vs 赛季中"做全文件扫描，两种模式：

- **模式 A**（ML2 不同、其余三档一致）：458935 处——**假阳性**。
  原因：ML2 的 data 块比其余小 131KB（4,902,829 vs 4,935,603 槽位），
  固定偏移对比必然错位。
- **模式 B**（四档两两不同且均在金额量级）：3709 处，其中 72%
  （2669 处）集中在 `0xDBF904~0xDE5214`。

### 新发现的结构：`0xDBF904` 处的 20 字节定长数组

| 偏移 | ML0 | ML1 | ML2 | ML13 | 说明 |
|---|---|---|---|---|---|
| +0x00 | 2899974 | 6193155 | 0xFFFFFFFF | 2834443 | 6~7 位数 |
| +0x04 | 8 | 8 | 0xFFFFFFFF | 8 | **严格递增序号** |
| +0x08 | 206636567 | 137446933 | 0 | 138445581 | 大整数 |
| +0x0C | 251748376 | 234921999 | 0 | 151035913 | 大整数（各记录接近） |
| +0x10 | 9 | 4 | 0 | 3 | 小整数 |

**判定：不是资金。** 对比 ML0 与 ML1 的 `+0x00` 序列可见其为同一组值的
不同排列 → 属**排序索引表**（按某键排序，不同存档序不同）。
模式 B 的"金额量级"筛选条件（1000~1e7 的 u32）过宽，导致假阳性。

该区域在 ML2 中整体为 `0xFFFFFFFF`/`0`，再次印证 ML2 为赛季前存档。

## 七、由此提出的新假说：余额可能是运行时计算出来的

若把现有证据串起来：

1. 存档里能找到**初始转会预算**（`+0x598`，赛季初分配值，跨进度稳定）；
2. 盲扫**始终找不到**"当前余额"（probe14/15/16 三轮穷举零命中）；
3. exe 侧存在 `MLAccountingTransferFeeDetail` / `MLAccountingSalaryDetail`
   这类**流水明细**类名（见 `docs/exe_analysis.md` 8.2）。

→ **假说：游戏存盘的是"初始预算 + 收支流水"，当前余额由运行时累加计算，
  并不以独立字段落盘。**

若成立，则"定位当前余额字段"这个目标本身就不成立，应改为定位**流水明细表**。
这可以解释既往所有失败。待验证。

## 八、下一步

1. **验证流水假说**：ML 里搜索"转会费/薪资流水"记录（应有金额 + 日期 + 类型三元组），
   可先按 `MLAccounting*` 相关字段形态在 exe 侧定位写出例程再回打。
2. **锁定 ptrBudget 的真实所指**：`0x16ECBF4`（23.9MB）超出 data 块（19.7MB），
   说明 `ptrBudget` 并非 data 块的直接映射，需先搞清它指向什么。
3. 回放 blob 路线不受影响，仍是独立可推进项。
