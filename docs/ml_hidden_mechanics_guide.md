## 一、每周推进：给全世界球员"过一周"

**宏观（社区已知道）**：游戏每周会扫一遍所有球员，处理状态、成长。

**此前未知的细节**：
- 游戏内部把一个赛季组织成 **82 周**，每周推进时把所有球员轮流处理一遍，然后
  **重置训练焦点点数 = 21**。
- 每周给每名球员**掷一个 0~99 的骰子**，按他的类型撞一张"11 档权重表"——
  像是抽卡掉率表。**涨不涨、涨多少，很大程度靠运气**，不是纯按潜力硬算。
- 球员每周算出来的状态会被**压缩打包**成一小段数据存进槽里：两个"发展比值"
  + 一个"模式位"（默认 2，还有一种备选 15）。

## 二、成长：怎么涨、怎么掉

**宏观（社区已知道）**：年轻人涨得快，老了会掉能力，成长带随机性。

**此前未知的细节**：
- 每项能力都有一条**成长系数曲线**：从 +1500 一路递减到 0，再跌到 **-1800**。
- 曲线的横轴 = **过赛季的次数**（球员每过一个赛季前进一格）。越过峰值后系数变负，
  能力值就**真的往下掉**，掉到下限为止。
- 完整公式（数值已解）：
  ```
  新能力值 = 旧值 + Δ
  Δ = (训练因子 ÷100) × 开发值 × [1.0 或 (110−旧值)×0.05，当旧值≥90 时] × 0.5
      + 一点随机抖动（骰 0~999）
  ```
  翻译成人话：周状态越好涨得越多、能力越高涨得越慢（≥90 用衰减）、老赛季系数转负
  就掉能力、每次还掺点随机的"运气"。
- 训练用的系数表覆盖 **25 项能力字段**（一部分是社区 Cheat Table 没逐位命名的
  "隐藏"能力：控球、长传/射门区段、GK 接球等——它们的成长曲线此前无人披露）。

## 三、训练焦点：每周发 21 点

**宏观（社区已知道）**：训练界面有"训练点数（Focus Points）"，上限 21。

**此前未知的细节**：
- 训练点分**8 个训练分类**各一个桶，总点数在 +0x0A（上限 21）。
- **每周自动补满 21 点**，上周分到某类但没用完的**原样退回**。
- 训练界面的分配就一件事：从这个分类桶加、从总点数减。

## 四、球员身上的"状态码"：谁还活着该成长

**此前未知**：
- 每个球员有一个 **4 位状态码**（内存偏移 0x13C 低 4 位），取值集合 **1~6**：
  - **5 / 6** = "跳过"类（退役/离队，赛季里不再处理这类球员）
  - **3**（含归并的 1 / 2）= "正常在队"（走属性位图维护）
  - **4** = 一种独立状态（具体含义仍在展开）
- 游戏靠这个开关决定"谁还该成长、谁不用管"。

## 五、存档里到底存了什么

**此前未知（且反直觉）**：
- 大师联赛的训练焦点、每周状态、成长过程——**全部不落盘**，只存在于游戏运行时的
  内存里。存档只存**结果**（球员能力值等）。
- 你不可能从存档文件里读出"这名球员这周的成长轨迹"；存档存的是"结算后的能力值"。
- 可变的部分（如预算）在存档里是**静态值**（4 个大师联赛样本完全相同），不是
  玩家可控的动态余额。

## 六、改存档：必须重算"指纹"

**此前未知（重要）**：
- 存档加密头 `encHeader[128:192]` 里存着 **数据块的 SHA-512 指纹**。
- 游戏**每次读档都会把这个指纹和实际数据对照，对不上就拒绝**。
- 所以想改存档（改能力、改钱），**必须连这个指纹一起重算**，否则游戏不认。

## 七、回放：里面没有坐标

**此前未知（打脸式结论）**：
- 回放文件里那 248 字节的"乱码"**不是压缩、不是加密、也不含球员坐标**。
- 真正的坐标是比赛时游戏现场从"姿态/动画码"算出来的，**根本不落盘**。
- 想从回放文件读"球员当时在哪"——这条路是死的。
