## 四、关键事实与教训（接手者必读）

1. **金额单位 = 100 欧元**（社区运行时实证，见 `docs/community_findings.md`）。
   此前按"万位/百万量级"做的资金扫描全部作废。
2. **存档布局 ≠ 内存布局**：社区工具的偏移是运行时内存偏移，不能直接照搬到存档；
   字段集合、语义、单位可用，具体偏移必须在存档上重新对拍。
3. **全库球员资料不在存档内**（多脚本交叉证伪）：来自游戏外部数据库
   `cpk_dat/common/etc/pesdb/`（Player.bin 等 28 张表）。存档里只有球员 ID。
4. **盲扫已证明不可行**：量级窗口法单样本噪声 4.7 万簇；资金定位必须走
   "游戏内真实数值 ×100 精确对拍"路线。
5. **社区生态优先**：本项目所有重大突破都来自站在社区既有成果上
   （pesXdecrypter、EconomyScaler、CT 表），而非从零硬扫。后续遇到新难题，
   先查社区有没有人解过。

## 六、未解项与推荐路线（按优先级）

1. **资金动态余额**（最高优先级）：需要玩家提供游戏内显示的账户余额、
   转会预算、工资预算三个数值，×100 后在解码数据全量检索，三值相邻命中即钉死。
   备选：玩家在游戏中完成一笔转会制造双存档差分。
2. **对阵双方字段**：赛事表参赛实体以列表形式出现、非成对；
   可结合球队数组队号与回放名单的魔数标记（2CBDFFFD 主/247AFFFE 客）交叉。
3. **回放事件流轨迹数据**：每帧槽包内约 248 字节高熵块，疑压缩或加密；
   建议先在 exe 侧找回放写出例程（exe 偏移 0x01FDC500 附近，
   见 `docs/exe_analysis.md`）确认是否有压缩调用。
4. **修改器实操**：改 data 后重新加密已可行（闭环成立），但头部 +0x30~0x50
   的 32 字节哈希区是否需重算未经游戏实测；回放每场该区域必变，需实验设计。
5. **可选支线**：BAL 编辑器混淆 IL 反编译（提取它的存档偏移常量）；
   用社区球队/球员 ID 合集把赛事表、回放中的数字 ID 批量翻译成名称。
